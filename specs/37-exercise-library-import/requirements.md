# 37 — Exercise-library import: requirements

18 September 2026. Proposed scope, not implemented. Programme extraction is spec 22; this feature moves a coach's or Premium Plus athlete's existing exercise catalogue into Persistence. Existing individual exercise CRUD/search remains spec 03.

- **EX-1 Eligibility/ownership.** Premium Plus and every paid coach tier may bulk-import into their own private catalogue. No coach role for athletes, no writes to system/public exercises, and no automatic disclosure of an entire coach library to clients. Assigned exercise access follows the existing assignment/offboarding model.
- **EX-2 Input/mapping.** CSV and XLSX first, with column preview/mapping for source ID, name, equipment, muscles, aliases, notes and optional YouTube/Vimeo link. Preserve original values and identify missing/invalid data. Legacy XLS is a later adapter unless safely supported by the evaluation; tell users how to export CSV/XLSX. Provisional limit 1,000 rows/10 MiB per import, subject to measured performance; never truncate silently.
- **EX-3 Resolution.** Match source ID from the same owner's prior imports first, then reviewed aliases/exact names and catalogue candidates. Let the user keep existing, create private copy or merge approved metadata. Name similarity alone never merges two movements. Duplicate links/names and ambiguous row identities require review. A private alias remains owner scoped and must not relabel the shared system exercise.
- **EX-4 Videos.** Retain validated source video links; do not download third-party videos or infer redistribution rights. User-owned video upload/bulk filename matching is a separately costed second stage, with preview of matches, format/size controls, storage lifecycle and explicit rights acknowledgement. No overwrite by filename alone.
- **EX-5 Optional AI.** Suggested equipment/muscle tags/cues are visibly suggestions requiring review, not clinically verified metadata. Do not invent a video or mandatory programme prescription from an exercise name. Deterministic mapping works without an AI call; optional assistance consumes the explicit AI budget.
- **EX-6 Commit/recovery.** No exercises change before confirmation. Accepted rows have stable receipt/source IDs and resumable idempotent processing. A failed row remains visibly failed; summary reports created/updated/skipped/failed counts. Retry cannot duplicate successful rows. Existing user edits never get silently overwritten by a stale import.
- **EX-7 Safety/evidence.** Owner isolation, duplicate/retry/cancellation, stale update conflicts, spreadsheet limits, external URLs and invalid fields are tested. Formulae/macros/external spreadsheet references are never executed. Screen-readable content is plain text. Provide row-specific actionable errors, source deletion and a retention policy.
